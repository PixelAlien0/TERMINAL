3-Tier Software Architecture

            
[ USER PRESENTATION LAYER ]
  • Terminal CLI : pos_system.py  (Interactive text menu)
  • Web Terminal : static/index.html & js/app.js  (Full graphical register)
           │
           │ HTTP REST API (Port 8000)
           ▼
[ APPLICATION & LOGIC LAYER ]
  • Web Server   : server.py      (Zero-dependency ThreadingHTTPServer)
  • Logic Engine : pos_core.py    (Stock check, 12% VAT math, receipt formatting)
           │
           │ Atomic JSON Persistence (_write_json via os.replace)
           ▼
[ LOCAL DATABASE LAYER ]
  • products.json      • transactions.json      • settings.json      • receipt.txt

          


          

            
End-to-End Sale Flow

            

              
Step 1:User inputs item ID or scans barcode (e.g. 8901001).

              
Step 2:System looks up item in products.json and validates stock count.

              
Step 3:Item is added to cart; cart checks that requested quantity does not exceed available stock.

              
Step 4:Cashier tenders payment; backend ensures cash_received >= total_due.

              
Step 5:process_checkout() runs under a thread lock: computes subtotal, 12% VAT, and change.

              
Step 6:Inventory is decremented in products.json and transaction is logged in transactions.json.

              
Step 7:42-character thermal receipt is generated and saved to receipt.txt.

Q1: How do you prevent negative inventory when multiple items are purchased?

              

                Answer: Stock is validated in two stages. First, the UI checks available = stock - current_cart_qty. Second, when checkout is submitted, _prepare_cart_items() inside pos_core.py inspects the fresh inventory on disk under a threading.Lock. If any requested quantity exceeds remaining stock, a ValueError is raised and the transaction is aborted before any stock is deducted.
              

            


            

              
Q2: How do you protect JSON files from being corrupted if the app is closed mid-save?

              

                Answer: We implement atomic file writes in _write_json(). The data is first written and flushed to a temporary file (e.g. products.json.tmp). Once write succeeds, os.replace() instantly swaps the temp file with the target file. Since os.replace is atomic at the OS level, there is never a corrupted or half-written file.
              

            


            

              
Q3: How is the 12% Philippine VAT calculated?

              

                Answer: In pos_core.process_checkout(), if tax_enabled is True, we calculate:
                
tax_amount = round(subtotal * (tax_rate / 100), 2)
                
total_due = round(subtotal + tax_amount, 2)
                
change = round(payment - total_due, 2)
                
Tax settings can also be toggled or updated dynamically via the Management Suite or settings.json.
              

            


            

              
Q4: How do the CLI Terminal and Web Terminal stay in sync?

              

                Answer: Both pos_system.py and server.py share the identical backend library pos_core.py, which points to the same JSON files on disk. The web app has a 4-second auto-sync poll (/api/sync) that checks file modification timestamps (mtime) and automatically refreshes whenever disk changes are detected.

How to Reset Data Files to Factory Defaults

              
If test data is messed up, delete the files or run this one-liner in Python:

              
import os; [os.remove(f) for f in ['products.json', 'settings.json'] if os.path.exists(f)]

              Next time pos_core is called, it automatically recreates clean seed products and settings.
